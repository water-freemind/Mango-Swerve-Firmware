# MaixCAM2 区域控制电机

当前已接入底盘 CAN 协同。视觉串口仍使用 `$VIS,<区号>,<TreeDX>\r\n`。作业参数见 `BSP/vision_motor.h`，完整流程见工作区根目录的《底盘与肘击装置CAN协同方案.md》。

## 接线与工程

- MaixCAM2 A21 / UART4_TX → STM32 PB11 / USART3_RX。
- 两块板 GND 相连，串口为 3.3V TTL，115200、8N1。
- 视觉使用 USART3：PB11=RX、PB10=TX，115200、8N1。USART2 不再初始化；OLED 仍为 PA2=SDA、PA3=SCL。
- 单向控制只需 TX→RX 和共地。STM32 PB10 仍每 500 ms 输出测速和 CAN 状态，可接串口工具 RX；工具也需设置 115200。
- 用 Keil 打开 `MDK-ARM/RED_Demo.uvprojx`，新增的 `BSP/vision_motor.c` 已加入工程。
- `Core/Src/usart.c` 和 `.ioc` 已同步配置 USART3 为 115200、收发模式，TIM1 初始占空比同步改为 0。

## 控制规则

视觉端持续发送 ASCII 帧：`$VIS,<区号>,<TreeDX>\r\n`，其中 CRLF 为实际回车换行。

| 区号 | 视觉位置 | 运行电机 | PWM 输出 |
| --- | --- | --- | --- |
| 0 | 无 Gmg | 全部停止输出 | 全部 CCR=0 |
| 1 | 左上 | 2 / B（BOUT） | TIM1_CH2 / PE11 |
| 2 | 右上 | 4 / D（DOUT） | TIM1_CH4 / PE14 |
| 3 | 右下 | 3 / C（COUT） | TIM1_CH3 / PE13 |
| 4 | 左下 | 1 / A（AOUT） | TIM1_CH1 / PE9 |

上电全部静止。进入作业区、底盘确认停稳并通过新视觉帧复检后，锁定对应区域电机执行一次动作。

1. 按当前配置以 100% 占空比打击 800 ms。
2. PWM 清零，等待 50 ms 再换向。
3. 按当前配置返回 800 ms。
4. PWM 清零，等待画面稳定后重新检测，有目标则继续，无目标持续确认后通过 CAN 请求 GO。

一次正反转动作约 10.1 秒，随后停止 0.5 秒，整个过程中其他三路电机 PWM 保持为 0。计时通过主循环状态机完成，不使用阻塞延时；每段实际时长为设定值加主循环调度延迟。电机没有位置闭环，因此正反各转 5 秒不保证精确回到原位。

动作开始后，目标消失、区域变化、串口超时或接收错误都不打断已经锁定的动作，也不排队执行新区域。动作完成后，全部电机停止输出 500 ms，然后等待一条新收到的区域 1～4 有效帧即可再次触发，同一区域也可重复，不再要求先收到区域 0。运行和等待 500 ms 期间的帧不排队，旧帧不会在等待结束后自动触发。视觉端持续发送同一区域时，每轮完成并等待 0.5 秒后，下一条帧会触发下一轮。

视觉信息超过 500 ms 未更新时，`Vision_Online` 清零、当前视觉区域清零；空闲时不启动电机，已经触发的动作继续完成。停止指 PWM 清零，实际制动/滑行行为取决于驱动器。

顺时针默认沿用 demo 的 IN1=低、IN2=高，逆时针为相反电平。实际机械方向须上板核对；如果某一路方向相反，在 `vision_motor.h` 将对应的 `VISION_MOTOR1_CW_IN1_HIGH`～`VISION_MOTOR4_CW_IN1_HIGH` 从 0 改为 1。

TreeDX 保存在 `Vision_TreeDX`，本功能不用于转向；允许 -2048～2048，以及无树标记 9999。解析器拒绝非法区域、缺失字段、额外字符、超长数字、超范围偏移及非 CRLF 帧；非法帧不刷新超时时间。

## 修改入口

- `BSP/vision_motor.h`：`VISION_MOTOR_PWM=80`（当前 ARR=99，范围 0～100）、`VISION_CW_MS=5000`、`VISION_CCW_MS=5000`、`VISION_REVERSE_PAUSE_MS=100`、四路方向配置，以及视觉接收超时和偏移限值。
- `BSP/vision_motor.c`：收帧、解析、超时处理和区域到电机的对应关系。
- `BSP/fun.c`：USART3 接收回调将收到的字节送给解析器，再重新启动接收；串口错误后清除旧帧并重启接收。
- `Core/Src/main.c`：主循环先调用 `Vision_UART_Task()`，替换原来四路同时运行的调用。
- 调试观察：`Vision_Region`、`Vision_TreeDX`、`Vision_Online`、`Vision_FrameCount`、`Vision_MotorRegion`（动作锁定的电机）、`Vision_MotorPhase`（0=空闲、1=顺转、2=换向停顿、3=逆转）。无目标合法帧的 Online 仍为 1，超时/接收错误后为 0。

已通过上述主机测试，以及改动 C 文件使用实际 HAL 头文件的 GCC 语法检查。尚未完成 Keil ARMCC5 完整构建、烧录和硬件联调。

上板可先用串口工具逐条发送以下内容，开启 CRLF 行尾：

```text
$VIS,1,-80
$VIS,2,9999
$VIS,3,0
$VIS,4,45
$VIS,0,9999
```

每轮先发 `$VIS,0,9999`，再发一个区域 1～4 的帧，确认对应电机顺转 5 秒、停 100 ms、逆转 5 秒并停止。动作期间发送其他区域或停止发送，确认不切换当前动作。动作结束后持续发送原区域，确认不重复启动；再发区域 0，然后发区域 1～4，确认重新触发。最后接入 MaixCAM2 核对四区与实际机构方向。

## OLED 显示

128×64 屏幕采用 6×8 字体，每 100 ms 刷新八行，示例：

```text
V:ON R:1 DX:-80
M:2/B CW PWM:80%
LEFT:4.8s BUSY
RX:125
A:300 RPM
B:0 RPM
C:0 RPM
D:0 RPM
```

- `V:ON/OFF`：视觉通信正常/未收到有效数据或超时；`R`：当前视觉区域，`DX`：树偏移，无树显示 `--`。
- `M:2/B`：正在执行动作的电机编号/字母，空闲显示 `M:0/-`；锁定电机与当前视觉区号可能不同。
- `CW` 顺时针、`CCW` 逆时针、`PAUSE` 换向停顿、`STOP` 停止；`PWM` 为当前阶段占空比，运行时 80%，停顿和空闲为 0%。
- `LEFT`：当前阶段剩余时间，向上取整至 0.1 秒；`BUSY` 动作中、`READY` 等待目标、`WAIT` 保留为空闲未就绪提示；当前动作完成后的等待由 `COOL` 阶段显示。
- `RX`：累计接收的合法视觉帧数；下四行是 A/B/C/D 四路实测转速。

原 OLED 的 CAN 自检信息由以上视觉/动作信息替换，CAN 自检与 USART3 状态输出继续运行。文字宽度已按 128 像素屏幕检查，显示及倒计时函数通过主机检查；实际屏幕显示仍需上板验证。

## OLED 黑屏排查补充

已修复当前 main.c 遗漏的 USART3 初始化、视觉动作任务，并移除旧的四路方向设置调用。开机初始化成功后先显示 `OLED OK / USART3 RX:PB11 / MOTORS STOPPED`，然后进入实时数据页面。此问题影响视觉联动，但尚不能单独证明是黑屏原因。

PB10 / USART3_TX 的 115200、8N1 状态输出追加：`OLED:<就绪状态> OE:<错误位> NACK:<未应答次数>`。`OE` 可组合：1=设备未应答，2=SCL 拉高超时，4=SDA 电平异常/总线忙。硬件未连接时不能靠电脑检查确定根因。

实际接线仍为 SDA→PA2、SCL→PA3、GND 共地、电源按 OLED 模块规格接入；视觉 TX 只接 PB11，不能占用 PA2/PA3。若 LED 正常闪但屏幕黑，优先查看串口错误及供电接线；若 LED 也不闪，需进一步用调试器检查启动位置和 OLED 初始化是否卡住。

本次修正已通过 Keil ARMCC5 完整构建，0 错误、0 警告，生成 HEX；未自动烧录。该构建结论不能替代上板显示验证。

## 上电立即显示

GPIO 初始化后立即调用 `OLED_PowerOn()`，在定时器、CAN 和串口初始化之前显示启动页面：`SYSTEM STARTING`、视觉离线/区域 0、电机停止/PWM 0%、等待 MaixCAM，以及四路初始 RPM。OLED 初始化包含 100 ms 的上电等待，显示仍需要一次 I²C 刷屏时间。

进入主循环后立即绘制第一帧实时数据，随后每 100 ms 更新。没有连接 MaixCAM、没有目标或 RX=0 都不阻止显示。`Init()` 不再重复初始化和清屏；初始化失败保留原每秒重试机制。该修改不消除 PA2/PA3 上外部串口设备与 OLED 同接造成的电气冲突。

区域接线确认：1 区控制 BOUT，2 区控制 DOUT，3 区控制 COUT，4 区控制 AOUT。OLED 的 R 显示视觉区域，M 显示实际电机编号/字母；例如 1 区运行时显示 `R:1` 和 `M:2/B`。

## 2026-11-04 允许连续打击

原先只触发一次的原因是动作完成后必须收到区域0才重新允许。已移除这项条件：一轮打击/返回完成后进入阶段4，全部 PWM 清零，等待 `VISION_RETRIGGER_DELAY_MS=500` 毫秒，然后进入阶段0等待新区域帧。即使区域与上一轮相同也可以触发。阶段4的 OLED 显示 `COOL`、PWM 0% 和剩余等待时间。

运行/冷却期间不缓存下一轮动作。只有返回等待指令状态后新收到的合法区域1～4帧才能触发，区域0或失联不会触发；目标持续可见且视觉持续发帧时，会一轮接一轮打击。其余时间、占空比和区域映射保持不变。
