# 芒果疏果赛题与 S21C/STP23L 底盘电控技术分析

> 分析日期：2026-10-07。本文是设计依据和待验证清单，不代表功能已经实现或上车验证。仅针对本仓库的 STM32H723 舵轮底盘电控；机械臂方案尚未确定。

## 1. 依据与结论

依据：2026-09-10 版《B 类“芒果疏果机器人竞技”比赛及评审规则》；WHEELTEC `WHEELTEC_S21C主控资料_V2.0_2025.05.21` 中的《S21C 主控使用说明》、S21C 原理图、`S21C搭配STP23L使用例程（2026.7.8）.zip`、ROS2 解算 SDK 和资料更新记录；乐动 STP-23L 独立数据手册、开发手册和 2025-10-10 使用手册；以及本仓库 `firmware/` 源码。传感器单独资料的参数、原始协议及 S21C 风险见[STP-23L 详审](stp23l-sensor-review.md)。比赛通知见[大赛官网](https://uiaec.ujs.edu.cn/news_show.php?id=234)。规则注明赛前以官网最后发布的版本为准，本文引用的本地附件不保证是最终版本。

**建议采用“已知场地图 + 舵轮/IMU 里程计 + 定向测距校正 + 通道索引”的自主导航，不以单点传感器承诺二维激光 SLAM。** 下文按 S21C 四路全部接入 STP23L 的能力上限分析；实际模块数量、安装朝向和采购情况尚未确认。S21C 到 STM32H723 优先评估 CAN 接线；S21C 的现成“串口输出”通过 Type-C/CH9102 给 USB 主机，资料未给出可直接插到底盘 UART 的独立 TTL 输出接口。当前固件只有遥控手动控制，比赛所需的自主导航、自动出场和停靠仍需开发。

## 2. 赛题对底盘电控的硬约束

| 规则 | 电控含义 |
| --- | --- |
| 场地 460 × 300 cm，6 条田垄、7 条垄沟；垄沟和唯一出入口标称宽 40 cm | 先量整车俯视外包络，包括轮胎、传感器和作业装置。场地尺寸允许 ±5%，故宽度要按可能的 38 cm 净空核查；代码中的 265.7 mm 长/宽是轮中心几何参数，**不能**当整车外宽。 |
| 垄间模式须遍历 7 条垄沟；跨垄模式须遍历 6 个垄背 | 当前舵轮底盘更适合先验证垄间模式。按已知地图建立通道序号和蛇形路线；端部换道需要实测横移、转向和装置扫掠空间。 |
| 两条沟随机铺约 5.5 mm 厚地毯，地面为 PE 爬行垫 | 轮径/打滑模型会随地面变化。验证轮速和 IMU 里程计在两种地面上的位移误差，不能只用空旷硬地标定。 |
| 5 分钟内完成作业、出场并自主停在 40 × 100 cm 启动区；出场不全或未停入启动区为 0 分 | 导航必须包括返回出入口、整车完全出场和停止确认。7 条沟若每条按约 2.2 m 计，直行段已约 15.4 m，尚未计换道、作业和返回；0.2 m/s 仅直行需约 77 s。 |
| 比赛中不得遥控或用电脑控制；起跑后不得调试 | 将现有遥控功能仅用于赛前开发，新增独立自主模式。比赛起跑方式、上电自检、失败降级都要不依赖上位机或无线遥控。 |
| 专本组 12 棵树、其中 10 颗绿色目标果；不作业计 0 分，误疏和碰撞有罚则 | 底盘需要能在目标树前稳定停靠，并给未来作业装置提供“到位/允许作业/作业完成或失败”的接口；先保证完整出场闭环，再优化时间。 |

资料中的果树高约 410 mm，枝叶/果实和底部围栏、垄侧处于不同高度。测距模块安装高度必须根据其实际光斑、最小量程和目标反射测试确定：低位测距用于通道边界，高位测距可能看到树或果实，不能把两者混作同一种地图观测。

## 3. S21C 资料包核查

| 项目 | 已核对结果 | 设计影响 |
| --- | --- | --- |
| 采集板 | S21C 为独立 STM32F103RCT6 板，可接四个 STP23L；四路模块与 STP23 不支持混用。 | 不需要把四路原始雷达串口直接接到 H723。 |
| 供电 | 手册写 Type-C 默认供电，外部电源输入 10–26 V；四个 STP23L 加板的手册功耗约 0.78 W。 | 选车载电源前核对实际电压范围、接地和启动/电机噪声；不可把电池线误接到 USB 或传感器信号脚。 |
| 对外数据 | 手册列 Type-C 串口 115200 bit/s 和 CAN 1 Mbps；原理图显示 MCU USART1 PA9/PA10 连 CH9102F，再到 Type-C。 | Type-C 是 USB 设备口，不是可直接与 H723 UART8 交叉接线的 TTL 口；如坚持 UART，需先确认实际板卡另有可用引出或设计转接。 |
| STP23L 例程 | `USER/main.c` 用 USART2/3/UART4/5 接四路传感器，`USART1_SEND()` 和 `CAN1_Send_Num(0x601, ...)` 对外发送。2026-07-13 更新记录称 2026-07-08 例程修复 CAN 通信问题。 | 使用 STP23L 对应的新例程，不混用 STP23、LD14P 或超声波工程。 |
| UART 帧 | `0x7B` + 4 个大端 `uint16` 距离（mm）+ 1 字节校验 + `0x7D`，总长 11 字节。例程 `Check_Sum()` 对前 9 字节逐字节异或，ROS2 SDK 的 STP23/STP23L 分支也用异或。 | 手册的校验名称不够明确，应以例程和实测帧为准；距离值是否有无效码仍需查传感器本体资料/实测。 |
| CAN 帧 | 1 Mbps、标准帧 ID `0x601`，8 字节按接口 1–4 顺序分别放大端毫米距离；帧内无时间戳或有效位。 | H723 收到时立即打本地时间戳，按实际发送周期判定过期；不要将 0 或其他异常值默认视为可靠障碍距离。 |
| 更新率差异 | 手册/`main.c` 注释写对外 20 Hz，但例程使用 72 MHz 时钟，TIM5 预分频 71、周期 19999，每 5 次中断才发送，源码推算为约 **10 Hz**。手册另称 STP23L 模块采样约 120 Hz。 | 传感器内部采样率不等于 H723 收到的四路新数据率。先抓取实测帧间隔；未验证前按较慢更新率安排安全余量。10 Hz 时车速 0.2 m/s 每帧前进约 2 cm，尚未计处理与制动距离。 |
| ROS SDK | 主要是 Linux 侧串口解析和 ROS 消息发布，不提供 H723 地图定位算法。 | 本项目不必引入 ROS；可参考其帧校验逻辑。 |

S21C 资料包另含 L14P/LD14P、STP23、六路超声波例程、芯片数据手册、三维模型和 PC 工具。这些是备选或开发辅助，不等于本次 STP23L 方案的功能。另已取得 STP-23L 独立资料：标称 0.07–7.5 m、近距平均误差指标 ±15 mm，输入 5 V、原始 UART 230400 bit/s。资料没有给出可靠的视场角、各材料失效码；详情和资料版本冲突见[STP-23L 详审](stp23l-sensor-review.md)。

## 4. 推荐通信与接线决策

**针对 DM-MC-Board02 的更新建议：S21C 使用独立 CAN3。** 达妙控制板 V1.1 手册标出第三路 CAN：扩展口 10 脚为 `CAN3_H`、12 脚为 `CAN3_L`，MCU 使用 PD12/PD13；本仓库已占用 FDCAN1（4 个达妙 6220 转向）和 FDCAN2（4 个 DJI M3508/C620 驱动），而 CAN3 尚未在固件中配置。S21C 例程输出经典 CAN、标准 ID `0x601`、1 Mbit/s、DLC=8。建议在确认用户实物确为这款板卡后，为 S21C 配置 FDCAN3，从硬件上与两路电机总线分开；具体线束、供电、终端和软件修改见[DM-MC-Board02 的 CAN3 接入方案](dm-board02-s21c-can3-plan.md)。S21C 板上有 120 Ω 终端，DM 板 CAN3 终端配置需实测确认；CAN3 收发器的使能/供电也需核对。若实际控制板不具备可用 CAN3，再依据总线拓扑评估并入 FDCAN1/2。

**可靠性补充：**当前 S21C STP23L 源码对外仅发送距离，未发送逐通道有效位、质量值或时间戳；四个 UART 处理函数在原始帧校验条件之外仍用第一个测量点写输出。接收 `0x601` 帧不能证明四个通道都收到新鲜且校验成功的数据。在用于自主避障前必须做逐通道断线/遮挡/坏帧试验，并据结果修正 S21C 固件或更换采集路径，详见[STP-23L 详审](stp23l-sensor-review.md)。

**UART 备选：** H723 工程中 UART8（PE0 RX、PE1 TX）已在 `.ioc` 配置但当前 `main.c` 不初始化，软件上有可复用空间；S21C 现成输出走 CH9102/Type-C。只有确认 S21C 的 3.3 V TTL 发送线能安全引出，并核对电平、地线后才考虑 UART8 接收。USB-A/Type-C 线不能替代 TTL 交叉线；给 H723 加 USB 主机链路会引入额外硬件和协议工作，不建议作为首版接法。

## 5. 导航与控制分层

1. **底层闭环**：保留现有 500 Hz 舵轮电机处理和 250 Hz IMU/轮式里程计；先量实车轮向、转向零点、轮径与地毯滑移。现有 `odom.c` 使用底盘 `cur_vx/cur_vy/cur_wz` 和 BMI088 估计位姿，尚未融合 S21C。
2. **测距输入**：CAN 接收中断只校验并缓存四路距离、到达时间和帧计数；固定周期任务处理滤波、异常值、过期帧和传感器健康，不在中断里运行导航。
3. **定位**：用已知场地和入口初始位姿初始化；里程计预测连续位姿。四路定向距离用于限速、防撞、走廊居中，以及端部/围栏几何校正。重复、平行的垄沟无法仅靠四个单点距离唯一确定“当前第几沟”；通道编号应由路线状态维护，并用端部/树位等可识别事件校验。纵向漂移、通道错数须通过实测闭环检验。
4. **路线状态机**：`等待起跑 → 进入场地 → 第 n 沟行进 → 树前停靠/等待作业 → 沟端换道 → … → 寻找出口 → 完全出场 → 启动区停靠 → 停车保持`。停止作业、测距超时、里程计异常或电机失联时进入受控停车/人工处置状态；比赛中不得依赖遥控继续行驶。
5. **作业接口**：机械机构未定，暂定抽象握手 `目标就绪/底盘已停稳/允许作业/作业完成或失败`，不指定电气引脚或通信帧。枝条方向有 0°–30° 变化，底盘到位精度与末端执行器容错应联合测试。

四点测距不提供连续二维扫描。若将来要求从未知场地自行构图、识别每棵树的精确位置或复杂避障，需要另评估扫描雷达/视觉方案；在本赛题的已知规则化地图上，先实现可验证的通道级定位更合适。

## 6. 实施顺序与验收证据

| 阶段 | 交付与检查 |
| --- | --- |
| A. 机械/电气可通行性 | 量整车及作业装置最大俯视外包络，检查 38 cm 出入口/沟道裕量和端部横移扫掠范围；确认 S21C 供电、CAN 终端、电缆长度和传感器安装高度。若无法安全通行，先调整机械布局。 |
| B. S21C 单板 | 用 STP23L 例程、USB 串口和 CAN 抓包记录四路距离、实际发送 Hz、抖动、无目标值、反光/黑色围栏/灰色垄侧读数；保留原始日志。 |
| C. H723 接入 | 新增测距驱动和时间戳/超时状态，确保上电时不误认零值；验证电机总线反馈和测距同时工作，无总线错误与控制周期丢失。 |
| D. 底盘里程计与路线 | 在 PE 垫和地毯分别量 1 m/2 m 直行、横移、转弯的误差；完成通道居中、端部换道、7 沟遍历和出口停靠，记录真实轨迹。 |
| E. 联合作业 | 加入识别/作业装置握手，逐树统计停靠时间、误疏/碰撞、总时间；完成至少一次无遥控、5 分钟内、全车出场并停入启动区的完整模拟赛。 |

当前底盘 `chassis.is_ready()` 只反映软件曾收到电机反馈，不能证明反馈仍新鲜；既有刹车请求也不能证明 CAN 帧已发送或实车已停止。自主赛前须补齐反馈超时、发送失败与实测制动距离的证据，尤其是靠近围栏、果树和出口时。此处是已知源码风险，不代表当前固件已经实现这些保护。

## 7. 尚待确认

- S21C/STP23L 的实物版本、CAN 线束与供电方式；四路传感器各自朝向、安装高度和光轴位置。
- STP23L 数据手册已确认标称量程、最小距离和实验室精度；视场角、无效值及对比赛黑色/灰色材料的实际表现仍待确认。
- 已提供当前设计的 352 mm 最大通行外廓；仍需确认其方向、包含的机构/转角状态与装车实测值。若为最大横向外宽，380 mm 净宽下仅每侧 14 mm 静态余量，详见[当前车体尺寸](current-chassis-dimensions.md)。作业机构扫掠范围、实际控制板 CAN 终端与拓扑仍待确认。
- 比赛最终规则、实际场地误差、起跑/停靠判定及是否有本校选拔的附加要求。
