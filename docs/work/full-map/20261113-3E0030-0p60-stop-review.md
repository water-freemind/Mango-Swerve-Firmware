# 3E0030本次0.60m/s：树位长等待与G3包络停车

本轮只读分析，不改参数、代码、烧录或发送运动命令。实际对象token7，NAV，行驶0.60、面板接近0.25；在约144.265秒时MAP_ENVELOPE中止，已完成7个树位，正在G3从第一树驶向第二树。当前新旧参数来源以原始日志为准，不沿用用户计划中的档位猜测。

## 现在为什么停

- 板端时间2454438ms，segment10，MAP_ENVELOPE。blockers=0、dt=10ms、remote在线，near=0、brake=0、stale=0；该次不是95mm或动态制动直接触发。直线测试状态中残留的UART_ERROR_OR_OVERFLOW不是这次地图停车原因。
- 故障附近周期状态：X1.540m、Y1.558m、航向88.48度。G3中心Y1.600m，下侧相邻垄上沿Y1.400m。当前地图车体包络各向155mm，按航向投影南侧跨度约159.1mm，估计南侧轮廓约1.399m，触到地图1.400m垄边。状态在故障后约0.4秒采到且数值有取整，不能据此宣称实际碰撞或精确越界1mm。
- MAP_FAULT为锁停，不会像普通PAUSED那样自行恢复。后续最新记录为零输出、停稳。

## 长等待的代码链条

运动控制允许在沿程20mm、横差20mm及终点航向4度范围内归零；完成条件另外要求定位残余创新≤10mm、观测收敛后的预期位置仍在20mm内，并连续400ms满足零指令、每轮停稳及车体速度/角速率条件。G5第二树的创新在正负方向不断跳动（近端窗口样本-16.4～+43.1mm），出现已归零却仍拒绝判稳、偶尔短促纠正后重新计时的链条。创新是观测和融合位置之间的残余，不等同实际位置偏差。

这次证据比上一轮8秒案例更明显，指向端点控制与观测完成门槛不协调。但日志只在2Hz采到POSE、10Hz采到stopped，缺少100Hz的逐项失败位与settled_s，尚不能逐次证明每次重置究竟由创新、轮速、角速率还是其它条件引起。不能为了快直接取消真实停稳或缩短2秒驻留。

## G3为什么控制和地图不一致

1. 2453687ms对束误差+25.2mm、front108/rear170，控制仍认为应向南修正；附近融合Y已降到1.590m（相对中心向南10mm）。2454062ms控制fb仍+23.5mm、指令vx=-0.047m/s。
2. 2454187ms出现active=0、frozen=1：冻结判断发现轮式横向里程变化超过30mm，而缓存的前后束相对检查点变化不超过5mm，撤销了对束约束。随后附近融合Y从1.564降至1.558，触发地图包络。
3. 故障原始front121/rear154mm，按当前对称安装和地图表面推算，对束差值反映约+16.5mm的北向偏差，与同期融合位置的南向36～42mm偏差方向相反。数据相邻而非严格同刻；这证明系统内部参考有明显不一致，不证明哪个等于真实位置。
4. 地图融合每次独立对束最多校正2mm、20mm/s；控制横向动作却可更快。轮式里程、缓慢融合与对束反馈可能因此拉开。冻结还可能来自缓存/中值源龄、轮式里程偏差/打滑或真实测距冻结，现有日志不能单独判定。
5. 当前短缺测保持没有明确区分普通缺帧与frozen这类主动失效；对束失效后控制参考的保持/平滑回退也可能继续作用。现有日志未记录真实源时间及命中的分支，不能断言此次必然使用了完整300ms租期；需要同时复审失效后的撤销条件和回退速率。
6. 边缘20mm预警只限制沿路线速度，并不直接钳制向边界运动的横向纠偏；出现参考不一致时，沿程减速无法独立阻止横向估计越界，最后由硬包络停车。

后激光95mm与车身后沿齐平的用户实测也说明安装几何应重新核对。当前模型安装原点±40.98mm、车体半包络155mm不是该测量的直接同义值。不得猜测修改其它传感器位置，也不应靠放宽包络掩盖内部参考冲突。

## 建议的修正顺序（未执行）

1. 端点增加紧凑失败条件位图和判稳累计时间，统一控制归零与允许判稳所用的端点参考。保留20mm/4度和完整2秒驻留，用连续独立帧、残余创新滞回/一致性判据避免测距轻微跨10mm就不断重置。
2. 对束参考、轮式里程和融合地图位置发生冲突时，应限制/暂停危险方向纠偏并重新确认来源；明确冻结/几何拒绝不应直接当作普通短暂缺帧延用旧参考。不能只加大Kp。
3. 根据实际危险法向约束纠偏速度并检查剩余制动距离，而不仅限沿程速度；保留硬地图与95mm保护。
4. 在实车测量基础上核对传感器安装坐标、车体外廓及轮式横向里程。用本轮G5与G3场景分别验证等待和包络冲突，再比较相同档位的完整轮次。
