0.90比0.50全图慢约11.1秒，而近端区累计多约16.0秒；较高档位在其它行驶段省下的时间被树点附近消耗。不同轮次仅各一轮，不能据此推导可靠性概率或承诺固定节省量。

## 直接证据与尚未区分的原因

1. **驻留没有拖长。** 本轮36次从TREE_DWELL到TREE_NEXT均约2.010～2.030秒，无重复驻留进入。不能通过缩短这2秒解决前面的等待。

2. **大部分慢点不是持续ALIGN。** 在估计±10cm窗口内，0.50/0.70/0.90分别采到75/105/108个TEST_MAP_POSE，其中ALIGN仅1/5/2个，而近零指令样本有58/76/89个。样本周期约0.5秒，不能由样本数换算精确轮向门控次数或精确零速秒数；短促门控可能漏采。

3. **定位残余创新与到位准入是主要线索。** 同窗口残余X创新绝对值超过10mm的样本分别48/56/61个。源码在到位时额外要求残余创新≤10mm、预测收敛位置在20mm内；几何控制又可能已在20mm位置/横差、4度航向窗内归零驱动。于是可能出现“指令已停，但到位判稳不通过”，或者观测跨门槛后短促微调，400ms连续判稳重新计时。超过10mm的创新是测距与融合位置之间的残余，不等同车身偏离目标10mm。

4. **不能把全部等待都归于10mm门槛。** 0.90的G3第二树，1105500～1110000ms区间的周期轮速多为0、stopped多为1、航向约88.9度、fb约2～4mm，仍延迟到1110083ms才进入驻留。部分时段pending低于10mm也未立即完成。现有日志不含100Hz的endpoint_observation_unsettled、settled_s和逐项失败条件，低频记录不足以区分两帧之间的创新跳变、短促轮速/角速率越界或其它计时重置。应补充到位条件诊断，不能仅凭低频样本宣称某一个条件解释了全部8秒。

5. **每轮停稳和连续判稳也参与。** 应用stationary要求每个驱动轮速度绝对值<0.05rad/s，约相当轮缘2.55mm/s；运动控制另查车体速度<0.01m/s、角速率<0.02rad/s，且需持续400ms满足位置、航向、零指令及观测条件。单次不满足会清空判稳计时。现有stopped=0采样包含正常接近和微动，不能直接定性为编码器噪声，也不应盲目放宽真实停稳保护。

6. **暂停并非树位拖延的全部。** 0.50在G6暂停1.089秒；0.70入口暂停1.411秒、G6两次0.691/0.504秒；0.90入口暂停2.112秒。最慢的0.90 G3/G5近端窗口没有地图保护暂停事件，不能归因于95mm近距或退让计时。

## 与上一车端C9FAA比较及解释更正

C9FAA已完成的三轮0.50耗时203.524/202.303/200.725秒，均值202.184秒；3E0030本次0.50为199.774秒，仅快约2.4秒，不能据单轮宣称整体更好。C9FAA三轮同定义近端累计54.200/44.617/44.533秒，3E0030本次38.379秒；此项基于估计位置，不能替代真实轨迹精度和用户对摆动的观察。

本次三档都完成、没有G4退让超时，是已观察到的改善；仍存在动态制动暂停和端点长时间等待。0.90近端累计最长，说明继续提高最高档不能直接解决树位调整。

更正此前对接近档位的解释：full_map_test.c中approach_speed只在work_enabled且work_slow时限制range_speed；NAV不启用该作业输入。因此旧版NAV的0.25与本次NAV的0.15不会直接改变树位逼近控制，不应把面板接近档差异作为本次NAV慢点的解释。NAV树位速度由沿程制动曲线、端点限速、横向纠偏、观测和轮向门控共同决定。

## 优化优先级（仅建议，未实施）

1. 在既有日志预算内压缩/替换字段，记录到位未满足条件位图及settle累计毫秒：沿程、横差、航向、观测残余/收敛位置、逐轮停稳、车体角速度、零指令和轮向。保持周期频率和生产缓冲限制，先精确识别重置源。
2. 统一控制归零与允许判稳的端点参考，避免控制认为已到、判稳仍因另一份观测误差持续拒绝。对10mm残余创新增加独立帧一致性/滞回或等价的收敛位置判定；保留实际20mm位置窗、4度航向窗、真实停稳和完整2秒驻留，不能直接把阈值整体放大。
3. 让端点最后几厘米的连续低速修正与观测判稳衔接，减少观测轻微跳动造成的停—动—重新计时。先在这三轮场景复现，再在相同速度下对照实车。
4. 不优先继续加最高速度、加大横向Kp、缩短2秒驻留或放宽95mm保护；这些都不能针对目前证据中的主要等待。
