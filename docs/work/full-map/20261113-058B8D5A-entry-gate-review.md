# 回退后两轮：G7停顿与G4/G2入口长时间调整

本次只检查和归档，没有修改控制代码或烧录。实际部署为058B8D5A；选取回退后最近两轮NAV，token1行驶0.50/接近0.15，token2行驶0.70/接近0.35。NAV中接近档不参与WORK/SLOW限速，不能将差异归因于接近档。

原始冻结日志与分析：`firmware/build/round-analysis/058B8D5A-two-rounds-20261113-212144/`，指针 `active-two-round-review.txt`。目录含source.log、逐段JSON、summary.json、focused-metrics.json和生产地图几何探针。源日志经历过控制板重新上电，脚本按时间回退区分epoch，再按GO token分轮，未将先前静态状态混入本轮。

## 已确认的直接原因

这两轮主要停在调轮门控，而非G7保护暂停。G7没有记录 `RANGE_PAUSE`；停止采样均可见 `g=100`（十六进制0x100）、`motion_phase=1`、vx=vy=wz=0。对应AutoMotion等待调轮放行时主动清零指令。`TEST_MAP_AISLE align=0`表示底盘驱动门控未放行，align=1才是允许输出，不能反读。

| 区域 | 0.50轮 | 0.70轮 |
| --- | --- | --- |
| G7横向段 | 存在多次调轮零指令采样；无G7保护暂停 | 存在调轮零指令采样；无G7保护暂停 |
| G4入口到首树开始驻留 | 约54.0s，86/108个POSE采样为调轮 | 约47.9s，77/96个POSE采样为调轮 |
| G2入口到首树开始驻留 | 约5.2s，未重现入口长时间调轮 | 约30.3s，43/61个POSE采样为调轮 |

入口计时从该段首个周期STATUS至首树TREE_DWELL事件，包含行驶、调整与判稳，不是纯静止时间；段起点有约0.5s日志量化误差。POSE只有约2Hz，不能据此精确数清每次短停次数或将采样占比当作逐周期占空比。

0.50轮后来在回场segment16记录CONTROL_MODE_CHANGED，未记录ROUTE_COMPLETE；0.70轮625263ms记录ROUTE_COMPLETE、12树全部完成。后者仍存在入口长等待，不能把完成等同于过程顺畅。本轮有ORIGIN、ARM、GO成功ACK，下行命令当时已恢复，不能沿用回退刚完成时“没有回执”的判断。

## 为什么重复出现在入口

1. **换垄终点的允许误差转成下一段横差。** 非树点沿程停车窗为20mm、判稳0.15s，换垄结束并不强制收敛到下一段要求的5mm横向死区。G4两轮起始Y=2.283/2.281，目标2.300，相差17/19mm；0.70轮G2起始Y=0.888，目标0.900。随后G4融合Y在2.271～2.287附近、G2在0.873～0.888附近，存在持续纠偏需求。
2. **20mm地图预警会将沿程速度突然压到0.05m/s。** 在G4前20秒，两轮融合X只从约2.81变到2.70；0.70轮G2前20秒只从约2.81变到2.74。日志中along在0.050与0.000之间反复切换；0.000表示此项不限速，并非要求零速度。入口横差、车体旋转包络和位置小幅变化让预警反复进入/退出。
3. **沿程限速改变了组合运动的方向。** 当前控制先计算沿程、横向和航向修正，再决定轮向；调轮未到位会清零驱动。入口只剩0.05m/s前进时，约0.05m/s的横向纠偏和航向修正占比很大，轮向目标对反馈变化更敏感。代码还会在准备目标不兼容时更新准备方向，存在门控反复关闭、重新准备的路径。
4. **入口尚未获得垄内短对束支持。** G4两轮前20秒的40个AISLE采样，active全部为0；0.70轮G2同样如此。处于X约2.7～2.8的侧通道/垄端交界时，短前后对束尚不满足双侧几何条件，无法用垄内已确认反馈快速消除横差。G4直到离开这段区域后，才较快推进到首树。

### 生产地图静态复核

使用原auto_route.c/auto_geometry.c，在相同X=2.750、Y=2.277，分别设航向88°和90°：实际车体包络两者均未越界；20mm预警包络在88°不通过、90°通过，因此沿程限制会在0.05与不限速之间切换。结果保存在margin-probe.log。

举例：23mm横差扣除5mm死区、乘3.2增益，未进一步限幅的横向请求为0.0576m/s；与0.05或0.50m/s沿程请求组合，平移方向分别约49.0°或6.6°。这是未加入逐轮旋转分量的静态示例，说明限速切换足以大幅改变准备方向；不能把它当作实车每个轮子的目标角。真实逐轮目标角、角差、准备hint和逐周期更新原因目前没有完整记录，仍不能唯一断言每次重闭都由同一个分支触发，或排除某轮转向跟随能力影响。

## “微调力度不足”的判断

已确认大量等待时不是已经发出持续强纠偏而车辆无响应，而是上层处于ALIGN并输出零驱动。轮式驱动在部分等待窗口也接近零速；现有日志不足以证明电机扭矩或电流上限过低。当前横向增益3.2、最大横向速度0.10m/s，对20～30mm误差理论上已有约0.048～0.080m/s请求，但反复关门会使它无法连续执行。直接增加增益还可能扩大轮向变化，不能单独解决这个闭环问题。

G7也有同类组合：0.70轮进入横向段后，融合Y一度4.433（中心4.400），北墙反馈error约40mm，伴随0.05限速、预测限速和调轮零指令；0.50轮亦有约20～28mm北墙纠偏和反复调轮。此次证据与之前0.70/0.80轮 `stale=0x2` 的保护暂停不同，不能继续只归为右侧观测接管问题。

另有独立保护事件：0.70轮G2首树已开始驻留后，573471ms因左侧可信观测缺失暂停，574081ms恢复，持续610ms，near=brake=0、stale=reject=1。2秒驻留重新计时，从首次驻留571762到完成576081共4.319s。这会再多等约2.3s，但不解释此前约30s入口耗时。

## 修订优先级及现有仿真的缺口

优先处理换垄终点与下一段横差要求的衔接、入口预警限速的连续性、调轮准备目标在噪声和微小航向反向时的稳定性，再调整可连续执行的纠偏速度；保留真实95mm、测距失联及硬地图包络停车。不能简单关闭轮向门控或移除边缘保护。

现有G4底盘模型从X=2.35开始，已在垄内；纵向入口模型到segment2就结束。这两个工况都没有覆盖现场X约2.8、Y偏20～30mm、航向摆动、短对束尚未建立时的横向入口。之前模型通过不能证明这个入口闭环已经解决。

下一轮候选应以这两轮入口工况建立反例，加入适当的转向滞后、轮向反馈和测距扰动；记录逐轮目标/实测角差、prepare hint、门控退出原因以及沿程限速来源。验收应同时要求入口耗时下降、门控重闭减少、实际横差收敛和最小测距符合保护边界。
