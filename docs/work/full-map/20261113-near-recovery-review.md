| 项目 | 候选值 |

| 接近五档 | 0.15 / 0.20 / 0.25 / 0.30 / 0.35m/s，启动默认0.15 |
| 入口前向制动模型 | 0.20m/s²；基础延迟0.35s，加源样本年龄（最多0.30s）；跟踪余量0.04m/s |

退让只用于HOST全图控制，需新鲜四向测距、有效定位和里程计、作业未锁车、目的方向有制动净空，且剩余退让走廊满足原地图车体包络。先停稳，再零驱动准备轮向，轮向反馈放行后才输出退让速度。数据过期、冲突障碍、≤80mm、未对齐或作业锁期间均保持零输出，首次计时不重置。超时或实测路程达限即结束任务。SWD停止、控制权切换、STOP、CAN/反馈故障、用户暂停以及真实地图越界仍优先；不延迟这些保护。

四向95mm是激光读数，不是车身外95mm净空。用户实测后方95mm与车身后沿齐平，此事实记录在此；本轮没有据此猜测四个传感器的地图安装坐标或修改车体尺寸。仍需独立标定地图坐标关系。实际运动时动态制动和地图包络可能早于95mm介入，不能把95mm理解为任何速度下的最终停车距离。

## 历史数据复审

读取13份20261112命名的原始串口日志，共183854509字节；其中最后一份跨午夜持续到11月13日。各文件SHA256、事件位置及统计保存在候选目录historical-log-review.json。统计是不同固件、不同会话的证据记录数，不合并解释为同一版本的独立故障次数。

1. A12A三轮：0.50/0.60/0.70m/s累计保护暂停分别1.212/2.409/6.837秒。入口是已接受左墙源超过300ms；其它主要是主测距拒绝后预算耗尽。原始输入尚新鲜与定位证据有效是两回事，保留源时间准入和有界主束衔接修复。完整三轮证据继续见20261113-three-run-analysis.md。
2. G4并非首次出现近距后地图越界。straight-console-20261112-165229.log第68779行记录near=0x4，第68903行对应后续MAP_ENVELOPE；straight-console-20261112-233558.log第378883行记录后测距99mm，随后第379107行对应93/92mm及MAP_ENVELOPE。行号按去除换行后的原始文本行计数。
3. 代码允许较近读数参与地图面融合。近障碍不一定是地图中的垄面，持续融合可能把估计位置拉向该地图面；这一风险已在简化闭环中复现。现在≤100mm的通道暂不作为地图面定位证据；这不是100mm停车阈值。恢复期间对应通道继续隔离，原始读数始终保留给95mm保护，不能以滤波或屏蔽定位来忽略近障碍。
4. 新增G4场景保持历史99→93mm输入：99mm不触发新95mm近距保护，也不拉动地图位置；93mm进入受限退让。仍不把历史估计位置漂移等同实际车体移动，更不能据日志认定当时发生实体碰撞。
5. G5第二树的融合收敛/完整驻留检查、零驱动准备保持和轮向门控继续保留。树位仍需完整2秒，未通过缩短驻留换速度。
6. 今日手持四向试验日志处于MANUAL/STOP，不存在对应全图保护触发事件，因此显示95/100mm差异不是四向软件阈值不同的充分证据。新阈值另有四通道94/95/96mm边界测试。
7. 历史日志还存在乱码、NO_VALID_STATUS_5S重连和IOException；本轮没有修改无线/DAP固件、USB驱动或确认通信根因。历史记录缺帧时不能把“未见事件”当作“没有故障”。

## 仿真与对照方法

电脑上的GCC直接编译真实C规划、定位、底盘运动学和应用调度代码，硬件接口由测试替身提供。软件逻辑闭环10ms一步，根据地图射线交点生成测距，可按100ms刷新并模拟源龄；注入3.2%轮式里程比例误差、航向扰动、延迟、突变、冻结与丢帧。

四轮模型运行真实IK/FK及轮向门控：轮向每10ms按误差0.12倍跟随且受转向速度约束，驱动速度按误差0.20倍跟随；另一些整图事务模型用车体速度误差0.25倍跟随。这些系数不是实车系统辨识结果，不模拟真实摩擦、载荷、打滑、电池变化和射束反射。作业模型的视觉区域、目标偏移和肘击握手也是模拟输入。

日志复现是按关键记录构造确定性场景，并非将全部183MB遥测逐帧原样重放。最终测试包括真实生产调度的准备→轮向反馈→退让，以及SWD立即停止；日志缓冲长度和阻塞预算也被检查，未新增周期日志行。
