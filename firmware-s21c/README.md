# S21C / STP23L 四路激光采集板

本目录为底盘仓库中独立维护的 STM32F103RCT6 采集板工程。H723仍在 `../firmware/`，两者分别构建，镜像不能混烧。2026-11-09从D盘原厂 `S21C搭配STP23L使用例程（2026.7.8）` 导入82个源码/头文件/启动文件及Keil配置；未导入OBJ、旧镜像和个人IDE状态。保留原WHEELTEC、ST、ARM声明，原件未修改。逐文件原始SHA256及来源见 `vendor-source.json`。入库副本规范了厂家文件的行尾及缩进空白，原始哈希用于来源追溯，不能当作修复后文件哈希。这是本机独立修复候选，不是队友电脑上尚未取得的版本。

## 结构与实现

| 路径 | 用途 |
| --- | --- |
| `USER/UART1.uvprojx` | Keil工程，已加入新解析器及适配层，开启C99；Keil本次未执行构建 |
| `src/stp23l.c/.h` | 无HAL依赖的有界流式解析、统计、逐路新鲜度和失效码 |
| `src/s21_board.c/.h` | 四路中断输入、IRQ保护的输出快照及调试计数 |
| `src/s21_transport.c/.h` | 周期输出路径的CAN/USB有界发送、撤销确认及失败统计 |
| `HARDWARE/usart2/3/4/5.c` | 保留厂家引脚/串口初始化，接收改接共享解析器 |
| `HARDWARE/time.c` | 按RCC的APB1时钟及倍频计算1ms时基，100ms请求发送；TIM5优先于四路接收 |
| `USER/main.c` | OLED、USB及CAN发送，统一使用新鲜快照，统计CAN发送失败 |
| `CORE/、STM32F10x_FWLib/、SYSTEM/` | 原CMSIS、标准外设库和板级代码；包含必要GCC兼容修改 |
| `gcc/` | 独立GCC启动/链接；向量顺序来自保留的ST HD启动，256KB Flash、48KB RAM与Keil配置一致 |
| `tests/` | 主机回归与当前H723 `laser.c`兼容检查，不接串口/下载器 |
| `build/` | 生成产物、日志；本目录忽略，不入版本库 |

四路对应 USART2、USART3、UART4、UART5；230400/8N1。保持板端接口顺序1–4，不在解析器中绑定车体方向。CAN仍是1Mbps、标准经典数据帧 `0x601` / DLC8，四个无符号16位毫米数按高字节先发；USB保持原115200、11字节封装。

协议依据：STP23L开发手册v0.1的PDF第5–6页。测量帧为4字节AA头、6字节地址/命令/偏移/长度、184字节数据、1字节累加和，总195字节。和校验不包含4字节AA头；数据为12个15字节点及4字节小端时间戳。只接受地址0、命令2、偏移0、长度184。

修复每字节重复消费、校验外发布、首点覆盖均值、16位累加及跨帧不清零。每路独立32位累加，只纳入 `1..15000mm`；负编码、零、超筛选上限不纳入。15000是与当前DM一致的传输筛选，不是传感器物理量程保证；不新增70mm下限。12点算术平均会改变首点行为，边缘/混合目标延迟与效果待台架验证。

仅完整校验成功且有有效点的新时间戳帧更新距离和 `last_valid_ms`；坏帧保留上次有效测量但不续期；全无效帧立即失效；重复时间戳不续期。时间戳不同允许模块复位/回绕，不假设其绝对时间与主控一致。UART硬件错误清除半帧，超过20ms的字节间隙重置半帧；坏帧后有界滑窗重新寻找包头。该累加和只能检错，不能保证发现所有内容损坏。

启动无测量或单路有效测量超过300ms时，在该路输出 **65535**；其余路继续独立工作。当前DM拒绝该值续期，并在自己的300ms接受值时效后判无效；两级超时和100ms发送节拍会叠加，不能宣称断线300ms内车辆已经停止。接口兼容测试只覆盖本仓库当前DM代码；外部USB/ROS使用者也应识别65535为无效，不能当65.535米距离。

调试器可观察 `s21_channels[0..3]` 的 `good_frames/checksum_errors/header_errors/empty_frames/duplicate_frames/uart_errors/last_valid_ms/sensor_timestamp`，以及 `s21_can_tx_failures`、`s21_usb_tx_failures`、`s21_can_init_status`、`s21_can_abort_fault`。`good_frames`统计累加和校验正确帧，可能含重复或无有效点；不能直接等同有效测量次数。主循环不发送附加诊断CAN帧。

## 通信与输出复查（2026-11-09）

| 链路 | 已核对的约定与修复 |
| --- | --- |
| 四路接收 | USART2 PA2/PA3、USART3 PB10/PB11、UART4 PC10/PC11、UART5 PC12/PD2；每路230400/8N1；SR后读DR清硬件错误，错误字节不入帧 |
| 并发与时基 | TIM5优先级0、接收优先级1；输出快照在保存/恢复PRIMASK的临界区内复制；GCC关中断加内存屏障。过期有效位锁存清除，防止断线旧值在完整32位时基回绕后重新出现 |
| CAN初始化 | 改用SPL `CAN_Init` 等待硬件MSR.INAK进入/退出确认，不再误等请求位；检查参数与36MHz PCLK1，不符则停止CAN输出。原理图标注8MHz晶振、当前系统配置72MHz；实物和时基仍待核验 |
| CAN输出 | 标准数据帧0x601、DLC8、四路大端毫米；同一快照先发送CAN，再发送USB/OLED。邮箱满立即失败，硬件失败计数；挂起约2ms请求撤销，再约2ms检查TME空邮箱位，撤销不确认则锁存并需复位；另有轮询次数上限防止时基停住后死循环 |
| CAN恢复边界 | 沿用单次发送、不自动重发旧测量；bus-off不自动恢复。软件撤销不能收回已经上总线的帧；真实错误与撤销延迟需在物理CAN总线上验证 |
| USB输出 | 同一CAN快照转换成11字节：0x7B、8字节数据、前9字节XOR、0x7D。发送检查TXE及末尾TC，全帧约10ms超时并计数，另有轮询次数上限；失败可能留下半帧，接收工具必须按帧头/长度/XOR重同步 |

例：CAN载荷`00 7B 7D 00 FF FF 12 34`对应USB`7B 00 7B 7D 00 FF FF 12 34 5B 7D`。数据中的7B/7D是有效二进制载荷，不能当分隔符截断；FFFF代表该路失效。USB异常不撤销CAN运行，也不会由本程序发送额外运动命令。

**累加和的实测限制：** 在固定测试报文的195个删字节位置中，有12个用例碰巧通过8位累加和校验；这是特定合成数据的结果，不是无线或实际UART误码概率。补修保留尾部AA作为可能的下一帧包头后，该组用例能重新收齐后续正确帧，但无法撤回此前碰巧通过校验的错误测量。保持传感器原协议就不能保证所有损坏均可检出；CAN自身CRC也不能纠正采集端已经接受的错误值。强校验/质量信息需要传感器协议或额外经过验证的上层机制支持，不能靠本次代码声称实现。

## 本机复现

以下命令在仓库根目录使用Windows PowerShell执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\firmware-s21c\tests\run-tests.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\firmware-s21c\build-local.ps1
```

主机需要MinGW GCC；固件用Arm GNU GCC，可设 `ARM_GCC_ROOT` 或传 `-Toolchain`，默认读取用户EIDE工具链。GCC构建直接读取Keil项目源列表，替换其启动汇编为GCC版本；不依赖旧OBJ。失败构建清除旧可烧录镜像。

2026-11-09复查后实跑通过：原解析/DM兼容回归、实际板级接收适配层及实际发送模块的主机测试；新增1560个单比特破坏、195个删字节位置、196个插字节位置、10万字节确定性噪声、校验尾AA、USB黄金载荷、邮箱满/失败/撤销/锁存、冻结时基、USB TXE/TC卡住及恢复。完整GCC构建42源通过，新增`src/`同时使用`-Wextra -Werror`；text/data/bss为10356/4/4604字节；HEX SHA256：`1955E17EAD8514E5A6B8A31C9F542925C278A5530A7F2CE9B9352C427B132373`。另检查76个启动向量与原HD顺序一致，四路接收/TIM5强符号存在，Keil项目引用无缺失或重复，82份厂家原件哈希未改变。

镜像 `build/s21c.hex`、`build/s21c.bin`、`build/s21c.elf`，日志 `build/build.log` 与 `build/tests.log`；校验清单为`build/communication-review.json`。保留的厂家OLED/串口代码有指针符号和未用变量等警告，newlib nosys有未实现文件IO警告；新增主机测试使用 `-Wall -Wextra -Werror` 通过。未声称完整工程零警告。

## 台架验收与维护边界

**尚未烧录或实机验证。** 首次部署应备份采集板原固件，保持整车停车，在独立台架确认晶振/72MHz系统时钟、1ms时基、约10Hz发送和四路串口。确认65535在当前DM侧引起预期的失效处理，再逐路断信号/断电、重连、遮挡、交换端口/传感器。保留原始UART帧、CAN载荷、各路计数及DM状态，测量从断线到实际停稳的延迟。测距台架通过后再做低速靠近与沿墙验收。

本次没有访问COM口、改变H723固件、自动烧录或改动已运行的VOFA配置。不要把这里的F103镜像用于H723，也不要把编译成功当作量程/光路/车辆制动验证。
